Turing

由父节点全权掌控的状态传播框架
不订阅 · 不递归 · 不泄漏

快速开始 GitHub

核心设计

不是又一个 Redux。Turing 把状态传播的控制权，彻底交还给父节点。

父节点负全责

子节点收到哪些状态，完全由父节点决定。不存在子节点自行订阅、父节点不知情的隐式模型。

框架零递归

框架只负责单层分发，传播链由业务代码显式书写。调用栈里每一帧都对应具名节点，故障精确定位。

无订阅即无泄漏

没有 subscribe，没有回调注册表。节点被移除后不再被任何结构引用，GC 自然回收。

双树分离

children 表达结构层级，hooks 表达状态订阅。职责分离，互不干扰。

三入口极简 API

只暴露 turing、dispatchAppState、_state。读、写、通知，各自独立。

业务 key 无关

框架不感知任何业务 key，不做白名单校验。新增状态字段零配置。

双树架构

同一批节点对象，同时存在于两棵树里。框架只遍历其中一棵。

children · 结构树

page
├── list
│   └── item
└── sidebar

框架不自动遍历。业务在 on[key] 里手动路由， 精确控制到具体子节点。

hooks · 状态树

root
├── page ── on.theme
│   ├── list ── on.theme
│   └── toast ── on.*
└── logger ── on.*

框架强制递归遍历。所有要收状态的节点， 必须挂进某一层的 hooks 数组。

Node extends Hook。Node 是 Hook 的超集，多出 name 和 children。 框架内部只认 Hook，从函数名 notifyHook 即可看出——children 根本不在框架的视野里。

API

整个框架对外只有三个口子。

暴露签名职责
window.turing (root: Hook) => void 挂载根 Hook，启动监听。单例，重复调用自动替换旧实例。
window.dispatchAppState (key, value?) => void 写并通知。value 缺省 = 纯通知；value 为函数 = updater。
window._state object 直接读写当前状态，不触发任何通知。

调用语义

调用效果
dispatchAppState('k', v)state.k = v → 通知 k 变更
dispatchAppState('k', fn)state.k = fn(state.k) → 通知 k 变更
dispatchAppState('k')不写 state → 通知 k 当前值
_state.k = v只写 → 不通知

Hook 接口

// 所有属性全部可选，{ name: '节点' } 就是合法 Hook
interface Hook {
  on?: Record<string, (value: any) => void>;
  hooks?: Hook[];
}

interface Node extends Hook {
  name?: string;
  children?: Node[];
}

为什么不用 subscribe？

因为订阅必然需要取消订阅，而取消订阅必然会有人忘记。

订阅式的问题

节点 A 订阅了全局 store，节点 A 被移除后忘了 unsubscribe，store 仍持有 A 的引用，GC 永远收不掉。这是订阅式架构的原罪。

Turing 的做法

行为定义在节点自身属性上（on），不向任何外部容器注册。节点被从 hooks 数组移除即断引用，无需任何清理代码。

代价是什么？

业务需要自己维护 hooks 数组——但这个数组本来就是显式的、可枚举的、可断开的。用一点样板代码，换彻底的确定性。

快速开始

零构建、零依赖。把下面这个文件复制进项目即可，或用 CDN 直接引入。

// 1. 定义节点：on 声明订阅，hooks 挂载子节点
function newList() {
  const item = {
    name: 'item',
    on: { theme: (v) => renderItem(v) },
  };

  const list = {
    name: 'list',
    on: { theme: (v) => renderList(v) },
    hooks: [item],       // 状态树：item 要收状态
    children: [item],    // 结构树：item 是 list 的孩子
  };
  return list;
}

// 2. 挂载根 Hook
turing({ hooks: [ newList() ] });

// 3. 触发
dispatchAppState('theme', 'dark');   // 写 + 通知
dispatchAppState('theme');            // 纯通知，值不变
window._state.theme = 'light';         // 直接写，不通知
